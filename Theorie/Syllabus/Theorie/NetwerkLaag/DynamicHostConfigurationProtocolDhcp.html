Dynamic Host Configuration Protocol (DHCP)

Zoals je weet moet iedere host in het TCP/IP netwerk over een IP adres beschikken. Dit adres is uniek in het ganse netwerk. Als gebruiker kan je zelf een statisch adres toekennen aan iedere host.

Dit heeft als voordeel dat je op ieder moment weet op welk IP adres een host terug te vinden is maar dit heeft enkele nadelen:

  • Je moet zelf bijhouden welke host bij welk adres hoort;
  • Je moet manueel dit adres invullen, samen met een subnetmasker en default gateway;
  • Als je verandert van netwerk moet je dit opnieuw invullen;
  • Je moet bijhouden welk IP adres nog vrij is en je moet op voorhand weten wat het subnetmasker is, samen met de default gateway;
  • Als je het IP adres verkeerd ingevuld hebt zodanig dat je een duplicaat krijgt op het netwerk dan krijg je een onstabiele verbinding.

Om al deze nadelen te verhelpen gebruiken we DHCP.

DHCP bestaat uit twee onderdelen:

  1. DHCP Client
  2. DHCP Server

Client en server werken samen wat betreft het ontvangen en dynamisch uitdelen van IP adressen in het netwerk. De DHCP Client is de host die het IP adres opvraagt en ontvangt van de DHCP server.

Dit alles gebeurt aan de hand van een DHCP handshake. De DHCP Client heeft bij het verbinding maken met het netwerk nog geen IP adres en stuurt meteen een DHCP discover pakket naar alle hosts in het netwerk. Dit gebeurt aan de hand van het broadcast adres: 255.255.255.255. Iedere host in het netwerk ontvangt bijgevolg een DHCP discover maar het is / zijn enkel de DHCP server(s) die erop zullen reageren met een DHCP offer.

Het DHCP offer pakket is een voorstel van DHCP Server naar de Client toe met een beschikbaar IP adres. Als de DHCP Client hierop ingaat stuurt hij een DHCP request naar de DHCP Server.

Als laatste bevestigt de server het IP adres via een DHCP Acknowledge en geeft daarbij ook nog bijkomende gegevens mee:

  • De default gateway (meestal het adres van de router)
  • Het subnetmasker
  • De lease time (hoe lang je het IP adres mag gebruiken)

Een client die op het netwerk blijft wacht niet tot de lease time afloopt. Halverwege vraagt hij verlenging met een DHCP request rechtstreeks aan zijn eigen server, dus zonder discover en offer. Antwoordt die server niet, dan begint de volledige handshake opnieuw.
