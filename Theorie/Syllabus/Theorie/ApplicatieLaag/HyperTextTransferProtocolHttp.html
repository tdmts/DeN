Hyper Text Transfer Protocol (HTTP)

Van een aantal dingen die we dagelijks gebruiken hebben we weinig of geen idee hoe ze precies werken. Een televisie, een auto of een browser om er maar enkele te noemen.

We hebben er notie van, we weten ongeveer wat de principes zijn maar de details zijn ons niet vertrouwd. In dit hoofdstuk proberen we dit voor HTTP iets duidelijker te maken.

Zoals je weet is een protocol een set van afspraken die gemaakt worden. HTTP is dus ook gewoon een set van afspraken. De partijen die de afspraken maken zijn in dit geval een client en een server. Client en server zijn in deze context geen machines maar wel programma's.

Het is natuurlijk zo dat het server programma meestal wel op een zwaardere computer zal draaien omdat er nu eenmaal veel clients mee kunnen verbinden maar in principe kan het server programma op eender welke machine actief zijn.

De set van afspraken slaat concreet op de boodschappen die uitgewisseld worden tussen client en server. Een client stuurt een request naar de server en deze stuurt een response terug naar de client.

Die request en response boodschappen zijn omschreven in een Request For Comments. Dit is een soort van discussieplatform waar verschillende 'experten' een voorstel indienen dat door anderen herzien kan worden. Die experten zijn soms individuen maar natuurlijk ook medewerkers van verschillende technologiebedrijven zoals Google, Microsoft en dergelijke meer.

Een HTTP request ziet er bijvoorbeeld zo uit:

GET /opleidingen/bachelors/elektromechanica/ HTTP/1.1

Host: hogent.be

Connection: close

User-Agent: Mozilla/5.0 (Windows; U; Windows NT 10.0; nl; rv:1.8.0.3) Gecko/20060426 Firefox/1.5.0.3

Accept: text/xml,text/html,text/plain,image/png,image/jpeg,image/gif

Accept-Charset: ISO-8859-1,utf-8

Zoals je kan zien is zo'n request vrij duidelijk leesbaar. We vragen aan de webserver de pagina hogent.be/opleidingen/bachelors/elektromechanica/ en wij gebruiken Firefox op het besturingssysteem Windows NT 10.0. Dit is handig om te weten voor de webserver omdat er soms een onderscheid gemaakt moet worden tussen een desktop en mobiele versie van een pagina.

De server stuurt een HTTP response terug die er bijvoorbeeld zo uit ziet:

HTTP/1.1 200 OK

Date: Thu, 08 Apr 2020 18:24:33 GMT

Server: Apache/1.3.29 (Unix) PHP/4.3.4

X-Powered-By: PHP/4.3.4

Content-Language: nl

Content-Type: text/html; charset=iso-8859-1

Connection: close

Content-Type: text/html

Content-Length: 49

<html>

<head>

</head>

<body>

</body>

</html>

Eerst en vooral is er de response code, die in dit geval 200 is. Dit betekent dat de pagina die gevraagd werd in het request gevonden is en de inhoud straks volgt. Een andere response code is bijvoorbeeld 404 en deze betekent dat de pagina niet gevonden kon worden.

Onderaan zie je HTML code, dit is de eigenlijke inhoud van de pagina. HTML staat voor Hyper Text Markup Language. Iedere browser wordt verondersteld HTML correct te kunnen weergeven. Je kan de HTML code van een pagina opvragen door in de browser rechts te klikken en dan te kiezen voor 'Toon broncode van deze pagina' (oid).

Nu je de basisprincipes kent van HTTP proberen we dit opnieuw te koppelen aan ons TCP/IP model.

HTTP is een protocol dat draait op de applicatielaag en dat betekent dat de direct aangrenzende laag de transportlaag is. Wie een client of server wil programmeren zal dus  niet enkel rekening moeten houden met de request en response boodschappen maar ook met de gegevens die nodig zijn in de header velden van die laag.

De keuze van transport protocol dat gebruikt wordt voor HTTP is eenvoudig te maken en is TCP omdat deze een volledige overdracht garandeert. Als je surft naar een website wil je de volledige pagina laden en niet, omwille van transmissieproblemen, gegevens verliezen.

Als we kiezen voor TCP dan is er natuurlijk de TCP header. Waar zowel client als server rekening mee moeten houden, is het poortnummer.

Voor HTTP is de afspraak gemaakt dat poortnummer 80 gebruikt wordt voor de server kant. Voor HTTPS is dat poort 443.

Een webserver is dus een programma dat luistert naar HTTP requests op poort 80 en een HTTP response terugstuurt naar een client. Populaire webservers zijn Apache, Nginx of Microsoft's Internet Information Services of IIS.

Een client is een programma dat een HTTP request verstuurt naar een webserver op poort 80 en een HTTP response ontvangt. Dit programma is dan bijvoorbeeld een browser.

In de industrie wordt HTTP niet enkel gebruikt om webpagina's aan te leveren via een browser. Het wordt ook gebruikt om bijvoorbeeld data door te sturen over productieprocessen of deze zelfs te automatiseren.

Bekijk eens onderstaand eenvoudig HTTP request:

GET /robot/position/ HTTP/1.1

Host: mijnbedrijf.be

En dan de bijhorende HTTP response:

HTTP/1.1 200 OK

Content-Type: application/octet-stream

Content-Length: 27

x: 10.990

y: 12.422

z: 68.366

De coördinaten zijn hier dynamisch en dit betekent dat gewone HTML code, die statisch is, niet voldoende zou zijn.

De oplossing hiervoor zou het gebruiken van een server side scripttaal zoals PHP of ASP.Net kunnen zijn. Deze zou dan in staat moeten zijn om data op te vragen van het productieproces en dit dan te renderen in het HTTP response.

Wie niet zelf wil programmeren kan ook aan de slag met tools zoals NodeRed. Wie geduld heeft kan wachten tot dit aan bod komt in 3 automatisering en wie geen geduld heeft kan  al eens zelf aan de slag. NodeRed is gratis.

Je zou op die manier een hele verzameling aan acties kunnen opmaken die meerdere machines uitlezen en aansturen. Dit is wat men dan een Application Programming Interface of API zou noemen.

Het voordeel van te werken via HTTP is dat je bijvoorbeeld een productieproces kan aansturen vanuit de browser en je daar geen andere software voor nodig hebt langs de client kant.
